# HTML Prototype Direction Contract

## Mode

Operate. The user is completing recurring recruiting tasks, so scan speed and reliable state take priority over product promotion.

## Direction Contract

**THESIS**: One workbench keeps a role, its recruiting stage, and its interview memory together. The screen refuses a marketing dashboard and hides no dates that affect action.

**OWN-WORLD**: Cool paper surfaces, graphite type, crisp rules, and compact field controls. Coral marks active recruiting progress, jade marks completed work, and blue marks source or metadata. Color communicates state instead of decorating panels.

**STORY**: The user sees which application needs attention, opens the correct interview round, writes the question and answer, then finds it again by company and role.

**FIRST VIEWPORT**: A stable 224px navigation rail sits beside a 310px role list and a flexible detail area. The detail header names the company and role; a horizontal eight-stage rail anchors the page; four interview controls sit immediately below it. The primary action remains in the page header.

**FORM**: Code-led desktop workbench with a responsive, stacked mobile state. Its structure is grounded in the supplied recruitment progress and interview archive screenshots. The reference screenshots stand in for a product composition, not a pixel-matched re-creation.

**SEED**: None. The Impeccable runtime is not installed in this workspace, and this Operate surface has a specific task and reference structure.

**FINISH**: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
